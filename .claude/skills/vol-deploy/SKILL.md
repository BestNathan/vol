# Vol Deploy

## Overview

The vol project uses **GHCR** as the container registry and **ArgoCD GitOps** for Kubernetes deployment. All images are built with either `REGION=cn` (China — rsproxy.cn mirror) or `REGION=global` (CI/GitHub Actions). Deployment is fully automated via ArgoCD's App-of-Apps pattern syncing from `deploy/argocd/`.

```
Code pushed → CI builds image → pushes to GHCR → ArgoCD syncs manifests → pods roll out → smoke test
```

## When to Use

Use for any Docker or Kubernetes operation. Symptoms that trigger:

- Running `docker build` with any Dockerfile in `dockers/`
- Pushing or tagging container images
- Deploying to Kubernetes or checking deployment status
- Modifying files in `deploy/argocd/`, `k8s/`, or `dockers/`
- Post-deploy verification or debugging ImagePullBackOff

## Deployment Architecture

```
dockers/                           GHCR (ghcr.io/bestnathan/*)
  vol-agent-server.Dockerfile  →    vol-agent-server:<sha>

deploy/argocd/                     ArgoCD (argocd namespace)
  root.yaml                    →    App-of-Apps root
  applications/                    Child Applications
    workloads.yaml             →    agent-server + docs-rs-mcp
    runtime-config.yaml        →    ConfigMaps + namespace
  manifests/                       Generated K8s YAML
    workloads/                     Deployments, Services, PDBs
    runtime-config/                ConfigMaps (auto-generated)
```

## Services, Dockerfiles, and Build Args

| Service | Dockerfile | Build Args | Registry Image |
|---------|-----------|------------|----------------|
| agent-server (data-plane) | `dockers/vol-agent-server.Dockerfile` | `ROLE=data-plane` | `ghcr.io/bestnathan/agent-server` |
| agent-server (control-plane) | `dockers/vol-agent-server.Dockerfile` | `ROLE=control-plane` | `ghcr.io/bestnathan/agent-server` |
| MCP servers | `dockers/vol-mcp-servers.Dockerfile` | _(none)_ | `ghcr.io/bestnathan/<mcp-name>` |

The `vol-agent-server.alpine.Dockerfile` and `vol-llm-ui.Dockerfile` exist but are not the primary deployment paths.

## Docker Build

### Prerequisite: Cargo Mirror Config

**CRITICAL for CN builds:** The Dockerfiles expect `.cargo/config.toml` with `rsproxy.cn` mirror to be available in the build context. The project's `.cargo/config.toml` already has this — it's copied into the builder stage automatically.

**If building from CI (GitHub Actions):** use `--build-arg REGION=global` to skip the China mirror and use official sources.

### Build Commands

```bash
# agent-server (China network — default):
docker build --build-arg ROLE=data-plane \
  -t ghcr.io/bestnathan/agent-server:<tag> \
  -f dockers/vol-agent-server.Dockerfile .

# agent-server (CI / global network):
docker build --build-arg ROLE=data-plane --build-arg REGION=global \
  -t ghcr.io/bestnathan/agent-server:<tag> \
  -f dockers/vol-agent-server.Dockerfile .

# MCP server:
docker build \
  -t ghcr.io/bestnathan/docs-rs-mcp:<tag> \
  -f dockers/vol-mcp-servers.Dockerfile \
  --build-arg SERVICE=docs-rs-mcp .
```

### Image Tagging

Use **immutable git short SHA tags** for deployment (this is what CI uses):

```bash
TAG=$(git rev-parse --short HEAD)
docker tag ghcr.io/bestnathan/agent-server:latest ghcr.io/bestnathan/agent-server:$TAG
```

ArgoCD syncs these immutable tags — changing the tag in the Deployment manifest triggers a rollout.

### Push to GHCR

```bash
# Login (requires GitHub PAT with write:packages scope)
echo "$GITHUB_TOKEN" | docker login ghcr.io -u <github-username> --password-stdin

# Push
docker push ghcr.io/bestnathan/agent-server:<tag>
```

## Kubernetes Deployment

### ArgoCD GitOps (Primary)

The entire deployment is managed by ArgoCD's App-of-Apps pattern:

```bash
# Bootstrap (first time only)
kubectl apply -f deploy/argocd/root.yaml

# Check sync status
kubectl -n argocd get applications

# Check workloads
kubectl -n vol-agent-system get pods,svc
```

ArgoCD auto-syncs from main branch. **Do not use deprecated `k8s/` deployment scripts** — they are not synced with the ArgoCD manifests.

### Runtime Config Sync

ConfigMaps (agents, providers, skills, sandboxes, MCP) are auto-generated by CI when source files change on main. To regenerate locally before testing:

```bash
python3 scripts/sync-configmaps.py
```

This updates `deploy/argocd/manifests/runtime-config/*.yaml` from:
- `.agents/agents/*.md` → `agents-configmap.yaml`
- `.agents/providers/*.toml` → `providers-configmap.yaml`
- `.agents/skills/*/SKILL.md` → `skills-configmap.yaml`
- `.agents/sandboxes/*.toml` → `sandboxes-configmap.yaml`
- `.mcp.json` → `mcp-configmap.yaml`

### Kustomize (Alternative)

For deployments that need customization without waiting for ArgoCD:

```bash
kubectl apply -k deploy/kustomize/overlays/control-plane
kubectl apply -k deploy/kustomize/overlays/data-plane
```

### Secrets (Manual, One-Time)

Secrets are NOT managed by ArgoCD. Create them manually:

```bash
# Provider API keys
kubectl -n vol-agent-system create secret generic agent-provider-secrets \
  --from-literal=ANTHROPIC_AUTH_TOKEN='<token>' \
  --from-literal=OPENAI_API_KEY='<key>'

# GHCR image pull secret (needed in every namespace that pulls images)
kubectl -n vol-agent-system create secret docker-registry ghcr-bestnathan \
  --docker-server='ghcr.io' \
  --docker-username='<github-username>' \
  --docker-password='<github-pat-with-read-packages-scope>'
```

## Post-Deploy Verification

### Smoke Test

```bash
# Auto-detect via kubectl
./scripts/smoke-test.sh --all

# Direct endpoint
./scripts/smoke-test.sh -H localhost:3001

# Control plane only
./scripts/smoke-test.sh --control-plane
```

The smoke test validates:
- HTTP health check (`/health`)
- WebSocket JSON-RPC connectivity
- Pod status
- Dependent services

### Manual Verification

```bash
# Pod status
kubectl -n vol-agent-system get pods -o wide

# Recent logs
kubectl -n vol-agent-system logs -l app.kubernetes.io/name=agent-server --tail=50

# Check image versions
kubectl -n vol-agent-system get pods -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.containers[0].image}{"\n"}{end}'

# Describe for errors
kubectl -n vol-agent-system describe pod <pod-name>
```

## Common Mistakes

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Building without rsproxy.cn in CN | `cargo build` hangs or fails downloading crates | The Dockerfile copies `.cargo/config.toml` — ensure it has rsproxy.cn mirror config |
| Using deprecated `k8s/` deployment | Manifests out of sync with ArgoCD | Use `deploy/argocd/` path; `k8s/` is legacy |
| Forgetting smoke test after deploy | Broken deploy goes unnoticed | Always run `./scripts/smoke-test.sh --all` |
| ConfigMap out of sync | Runtime uses stale agent/skill definitions | Run `python3 scripts/sync-configmaps.py` before deploy |
| Missing image pull secret | `ImagePullBackOff` / `ErrImagePull` | Create `ghcr-bestnathan` secret in the namespace |
| Wrong Dockerfile for service | Build fails or incorrect binary | Use the service-Dockerfile mapping table above |
| Building with wrong ROLE arg | agent-server starts with wrong config | `ROLE=data-plane` or `ROLE=control-plane` |
| Not pushing image before ArgoCD sync | ArgoCD can't pull the image | Push to GHCR before updating image tags in manifests |
| Missing GITHUB_TOKEN env var | `docker push` fails with unauthorized | Export `GITHUB_TOKEN` (PAT with `write:packages` scope) |
| Using `kubectl apply -f` instead of ArgoCD | ArgoCD selfHeal reverts your change | Either commit to git and let ArgoCD sync, or use Kustomize overlay |

## Red Flags — STOP and Check

- "I'll just kubectl apply this manifest directly"
- "The smoke test can wait"
- "rsproxy.cn is probably configured already"
- "I'll tag it as latest and ArgoCD will pick it up"
- "The secrets are already in the namespace"

**All of these mean: follow the deployment workflow. Smoke test after every deploy. Use ArgoCD. Verify image tags.**

## Deploy Checklist

Before deploying:

- [ ] Image built with correct Dockerfile and build args
- [ ] Image pushed to GHCR with immutable tag (git SHA)
- [ ] Image tag updated in deployment manifest (or CI did it)
- [ ] Runtime config synced (`sync-configmaps.py` if needed)
- [ ] GHCR pull secret exists in target namespace
- [ ] Provider secrets exist in target namespace

After deploying:

- [ ] ArgoCD shows synced and healthy
- [ ] Pods are running (`kubectl get pods`)
- [ ] Smoke test passes (`./scripts/smoke-test.sh --all`)
- [ ] Logs show no errors
